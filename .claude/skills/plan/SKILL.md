# プラン作成

## ルール

- 実装前に必ずプランを作成する
- プランは対象 Issue のコメントとして投稿する
- Issue のスコープを超えない内容にする

## 手順

### 0. プランモードに入る

`EnterPlanMode` でプランモードに入ってから手順 1〜3 を行う（`/model opusplan` なら計画を Opus で立てられる）。すでにプランモードなら省略する

### 1. Issue を確認する

Issue 番号が `$ARGUMENTS` で渡された場合はその Issue を確認する。渡されていない場合はユーザーに確認する。

```bash
gh issue view {番号}
```

### 2. 関連ドキュメントを確認する

Issue の内容に応じて `docs/` 配下の関連ドキュメントと `proto/` を確認する。ConnectRPC・buf・protobuf の API は推測せず context7 で確認する。

### 3. プランを作成する

プランには以下を含めること:

- **概要**: 何をするか（1〜3 行で簡潔に）
- **背景・目的**: なぜこの実装が必要か（Issue 本文をそのまま貼るのではなく、自分の言葉で整理する）
- **仕様**: 具体的な振る舞い・ルール・エッジケース
- **実装手順**: ステップごとの変更内容（ファイルパス・関数名レベルで具体的に）
- **スコープ外**: 今回やらないこと（スコープ超過の防止）
- **テスト・確認手順**: 実装後にユーザーが動作確認できる手順
- **影響範囲・リスク**: 既存機能への影響、破壊的変更など（該当する場合）

### 4. プランをユーザーに提示する

Issue にコメントを投稿する前に、`ExitPlanMode` でプランを提示して承認を取る。

### 5. Issue にコメントとして投稿する

承認されたら（実行モードに戻ってから）対象 Issue にコメントとして投稿する。プランモードのままでは投稿できない。

```bash
gh issue comment {番号} --body-file -
```

（標準入力からプラン本文を渡す。HEREDOC を使うとフォーマットが崩れにくい）
