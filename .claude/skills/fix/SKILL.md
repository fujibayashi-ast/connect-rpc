# PR レビュー対応

## ルール

- レビューコメントを個別に確認し、1 つずつ対応する
- 対応しない指摘はその理由をコメントで返す
- 元の PR のスコープを超える修正は別 Issue に切り出す

## 手順

### 1. PR とレビューコメントを取得する

PR 番号が `$ARGUMENTS` で渡された場合はそれを使う。渡されていない場合はユーザーに確認する。

```bash
gh pr view {番号} --comments
gh api repos/{owner}/{repo}/pulls/{番号}/comments
```

### 2. 未対応のコメントを整理する

レビューコメントを列挙し、以下を判定する:

- 修正で対応するもの
- 設計判断として対応しないもの（理由をコメントで返す）
- スコープ外として別 Issue に切り出すもの

ユーザーに一覧を提示して方針を確認する。

### 3. 修正を実装する

「修正で対応する」と判断したコメントに対して順に修正する。

- レビュアーの意図を汲み、部分修正で済ませず根本原因に対処する
- 修正がプランから乖離する場合は Issue コメントのプランを更新する

### 4. セルフレビュー

`/review` スキルで変更をセルフレビューする。

### 5. コミット・push

変更をコミットし、PR ブランチに push する。

### 6. レビュー返信

レビューコメント（または PR 全体のコメント）で対応状況を返す。

- 修正したもの: どの commit で対応したか
- 対応しないもの: 理由
- 別 Issue 化したもの: 新 Issue 番号
